# Meshtastic ↔ Bitchat bridge (Windows)

Мост между радиосетью **Meshtastic** (LoRa) и **Bitchat** (Bluetooth LE).

* Новые сообщения из LoRa **автоматически** приходят в Bitchat на телефон.
  Уже доставленные сообщения повторно не отправляются.
* Сообщения из Bitchat **не уходят в LoRa автоматически**: они копятся в
  буфере, а отправляются только по команде из меню — направление, количество
  (последние 5/10/20/50) и при желании период повтора.
* Есть режим **полной синхронизации в обе стороны** — каждое новое сообщение
  сразу уходит на другую сторону.
* Телефон Bitchat выбирается при запуске, чтобы мост не сцеплялся с чужим
  устройством по соседству.
* Отправка в LoRa ограничена по скорости, чтобы не забивать эфир.

Основано на [GigaProjects/meshtastic-bitchat-bridge](https://github.com/GigaProjects/meshtastic-bitchat-bridge),
исходная версия лежит в `upstream/`. Текущая версия переписана под:

* актуальный протокол Bitchat (zlib-сжатие, PeerID из Noise-ключа, фрагментация);
* Windows (BLE-централь через WinRT/bleak, TCP-подключение к радио);
* интерактивное меню с поиском устройств и выбором по номеру;
* умную синхронизацию без повторной отправки старого;
* работу с VPN (сканируются только реально подключённые сети);
* тихий режим без логов и автоматическую очистку лог-файла.

> **Код написан с использованием ИИ.** Значительная часть кода создана
> ассистентом (ИИ) под руководством автора: архитектура, протокол Bitchat,
> логика поиска и синхронизации. Проверяйте код перед использованием в
> ответственных сценариях.

## Что нужно

* Windows 10/11 с включённым Bluetooth-адаптером.
* Радио Meshtastic, доступное одним из способов:
  * по Wi-Fi (TCP, порт 4403) — рекомендуется;
  * по USB (COM-порт);
  * по Bluetooth LE (только если на радио **выключен** Wi-Fi: на ESP32 BLE и Wi-Fi
    не работают одновременно).
* Телефон с открытым приложением **Bitchat** рядом с компьютером.
* Python 3.10+ (проверено на 3.14).

## Установка

```bat
install.bat
```

Скрипт создаст `.venv`, поставит зависимости из `requirements.txt` и
подготовит `config.json` из `config.example.json`.
Дальше всё запускается через `run.bat` (или ярлык на рабочем столе).

> `config.json` содержит ваши адреса устройств и поэтому не попадает в git —
> в репозитории лежит только `config.example.json`.

## Запуск

Двойной клик по `run.bat` (или по ярлыку **Meshtastic-Bitchat** на рабочем
столе). Откроется окно с меню:

```
============================================================
  Meshtastic ↔ Bitchat — выбор радио
============================================================
  1) Wi-Fi  — найти Meshtastic в локальной сети
  2) Bluetooth — найти Meshtastic по BLE
  3) USB    — список COM-портов
  4) Ввести адрес вручную (IP / COM / BLE)
  0) Выход
```

1. Выберите способ подключения цифрой.
2. Мост просканирует сеть/порты и покажет найденные радио с номерами:
   ```
   1) Radio-A — 192.0.2.10:4403 (Wi-Fi)
   2) Radio-B — 192.0.2.11:4403 (Wi-Fi)
   0) назад
   ```
3. Введите номер нужного радио — мост подключится.
4. Затем мост ищет **телефоны Bitchat** и предлагает выбрать свой. В списке
   только те устройства, которые реально ответили как Bitchat; для каждого
   показывается Bitchat user ID, ник, MAC-адрес и уровень сигнала:
   ```
   Найденные устройства Bitchat:
     1) @a1b2 — «Alex» — 02:00:5E:10:00:07 — -24 dBm
     0) не выбирать — подключаться к любому
   ```
   User ID — это первые 4 символа Bitchat peer ID (8 байт), которые Bitchat
   использует и в своём fallback-имени `anon####`. ID берётся из
   Bitchat-announce: мост на несколько секунд подключается к каждому
   кандидату, ждёт его announce и отключается.

   Почему в списке не все найденные адреса: iOS меняет Bluetooth-адрес
   телефона для приватности, а Windows помнит старые адреса и продолжает
   показывать их в сканировании. Такие «фантомы» не отвечают на подключение,
   поэтому мост их отбрасывает и объединяет ответившие адреса одного телефона
   в одну строку.

   Если рядом чужой телефон с Bitchat, выберите свой — мост будет работать
   только с ним и не отправит ничего постороннему. `0` оставляет прежнее
   поведение (подключение к любому найденному Bitchat).
5. После подключения появится **выбор беседы**. Названия берутся из каналов
   самого радио, поэтому в списке только реально настроенные беседы:
   ```
   Выберите беседу:
     1) Общий канал
     2) Личный чат с узлом…
     0) назад
   ```
   Если на радио настроены дополнительные каналы, они появятся здесь под
   своими именами (например, `2) Семья`, `3) Работа`). Выключенные каналы
   не показываются.

   «Личный чат с узлом…» показывает **все** узлы из нод-базы радио
   постранично (по 20). Номер узла сквозной: можно сразу ввести `25`,
   а `n` / `p` листают страницы; также можно ввести short name или `!id`.

Список каналов и узлов читается из самого радио. Если нужного приватного
канала в списке нет — сначала добавьте его на радио (в Meshtastic-приложении,
раздел Channels), затем перезапустите мост.

После запуска в консоли доступны команды:

```
  s — синхронизация (направление, 5/10/20/50, период)
  l — состояние буферов и расписания
  q — выход
```

Остановить можно также через `Ctrl+C` в окне.

### Синхронизация

**Meshtastic → Bitchat — автоматически.** Каждое новое сообщение из LoRa
сразу уходит на телефон. При повторном подключении телефона досылаются
только те сообщения, которые ещё не были доставлены; повторно старое не
отправляется.

**Bitchat → Meshtastic — только вручную.** Сообщения из Bitchat копятся в
буфере (последние 100). Чтобы отправить их в LoRa:

1. Нажмите `s` в консоли моста.
2. Выберите направление: `Bitchat → Meshtastic`.
3. Выберите количество: последние **5 / 10 / 20 / 50**.
4. При желании задайте период повтора: каждые N минут или каждые N дней.
   При повторе отправляются только новые сообщения, без дублей.

При отправке в LoRa мост выдерживает интервал (по умолчанию 10 секунд между
сообщениями), чтобы не забивать эфир. Устаревшие сообщения, слишком долго
пролежавшие в очереди, отбрасываются.

### Полная синхронизация в обе стороны

Если нужно, чтобы **каждое** новое сообщение сразу уходило на другую сторону
(а не только LoRa → Bitchat), включите полный режим в меню синхронизации:

1. Нажмите `s` в консоли моста.
2. Выберите `3) Полная синхронизация в обе стороны (сразу)`.
3. Выберите `1) включить`.

После включения новые сообщения из Bitchat сразу ставятся в очередь LoRa
(с тем же безопасным интервалом между отправками), а новые сообщения из LoRa
сразу уходят на телефон. Уже накопленные сообщения из обоих буферов
отправляются при включении. Выключить можно там же — пункт `2`.

Режим также задаётся в конфиге (`"full_sync": true`) или флагами
`--full-sync` / `--no-full-sync`.

### Адресация прямо из Bitchat

Даже если выбран общий канал, сообщению можно задать адрес. Оно попадёт в
буфер с нужным адресом и уйдёт в LoRa при ручной синхронизации:

| что написать в Bitchat | куда уйдёт при синхронизации |
|---|---|
| `привет` | в выбранный чат (канал по умолчанию) |
| `#1 привет` или `/c1 привет` | в канал 1 |
| `/dm A1B2 привет` | личное сообщение узлу `A1B2` |
| `/dm !a1b2c3d4 привет` | личное по ID узла |
| `/ch` | мост пришлёт в Bitchat список каналов радио |
| `/help` | краткая подсказка по командам |
| `/sync` | напомнит, как открыть меню синхронизации |

Ответы моста приходят в Bitchat от пира `MeshBridge` с префиксом `[Bridge]`.
Входящие из приватного канала помечаются как `[Mesh: имя / ИмяКанала] ...`,
личные — как `[Mesh DM: имя] ...`.

### Запуск с параметрами

```bat
run.bat --host 192.0.2.10
run.bat --port COM4
run.bat --ble AA:BB:CC:DD:EE:FF
run.bat --bitchat 11:22:33:44:55:66   & rem работать только с этим телефоном
run.bat --full-sync
run.bat --no-menu
run.bat --host 192.0.2.10 --debug
run.bat --test-send "проверка связи"     & rem отправить одно сообщение в LoRa и выйти
```

Параметры командной строки перекрывают `config.json`. Если указан `--host`,
`--port` или `--ble`, стартовое меню выбора радио не показывается, но команды
`s` / `l` / `q` в консоли остаются доступны. `--no-menu` отключает и их.

## config.json

```json
{
  "name": "MeshBridge",
  "chat": {
    "kind": "channel",
    "index": 0
  },
  "ble_scan_seconds": 3.0,
  "bitchat_target": "",
  "bitchat_peer": "",
  "full_sync": false,
  "history_limit": 100,
  "lora_send_interval": 10.0,
  "lora_stale_seconds": 1800,
  "log_file": "bridge.log",
  "log_truncate_seconds": 300,
  "quiet": true,
  "menu": true
}
```

В поставке **нет предустановленного адреса радио** — только порт по умолчанию
4403. Радио и телефон Bitchat запоминаются в `config.json` после того, как вы
выбрали их в меню (или задали через `--host` / `--port` / `--ble` /
`--bitchat`).

| поле | смысл |
|------|-------|
| `transport.kind` | `"tcp"` (Wi-Fi), `"serial"` (USB) или `"ble"` (Bluetooth). |
| `transport.target` | IP-адрес, COM-порт (`"COM4"`) или BLE-адрес. |
| `name` | ник моста, который видно в Bitchat. |
| `chat` | беседа по умолчанию: `{"kind": "channel", "index": 1}` или `{"kind": "dm", "node": "A1B2"}`. Режим `{"kind": "all"}` транслирует все каналы и личные (можно задать только через конфиг/`--chat all`). |
| `ble_scan_seconds` | длительность одного прохода BLE-сканирования. |
| `bitchat_target` | BLE-адрес(а) телефона, с которым разрешено работать. Если телефон сменил адрес, адреса перечисляются через запятую. Пусто — подключаться к любому найденному Bitchat. |
| `bitchat_peer` | Bitchat peer ID выбранного телефона (16 hex-символов). Не меняется при смене Bluetooth-адреса, поэтому по нему мост узнаёт свой телефон и отказывается от чужого. |
| `full_sync` | `true` — полная синхронизация в обе стороны сразу (LoRa ⇄ Bitchat). |
| `history_limit` | сколько последних сообщений хранить в каждой стороне (по умолчанию 100). |
| `lora_send_interval` | минимальный интервал между сообщениями в LoRa, секунды. Защита эфира от спама. |
| `lora_stale_seconds` | через сколько секунд отбрасывать устаревшие сообщения из очереди. |
| `log_file` | файл лога. По умолчанию туда пишутся только предупреждения, и файл очищается каждые 5 минут. |
| `log_truncate_seconds` | как часто принудительно очищать лог (по умолчанию 300 секунд). |
| `quiet` | `true` — тихий режим (без подробных логов). |
| `menu` | показывать меню при запуске без параметров. |

Без меню чат можно задать флагами:

```bat
run.bat --chat all
run.bat --chat 1              & rem канал 1
run.bat --chat dm:A1B2        & rem личный чат с узлом A1B2
run.bat --chat "dm:!a1b2c3d4"
run.bat --history 200         & rem хранить последние 200 сообщений
run.bat --lora-interval 20    & rem отправлять в LoRa не чаще раза в 20 секунд
```

Для отладки: `run.bat --debug` — подробный лог (файл всё равно очищается
каждые 5 минут и после обрыва связи).

Если транспорт в конфиге не задан (`transport` отсутствует), мост сам ищет
радио: сначала в локальной сети по порту 4403, потом на COM-портах.

## Как пользоваться

1. Запустить `run.bat`, выбрать радио и беседу.
2. В консоли появится:
   ```
   [LoRa] подключено: Wi-Fi 192.0.2.10:4403 — узел A1B2
   [Bridge] мост привязан к: канал 0 (Primary)
   [Bitchat] телефон подключён
   ```
3. Сообщения из LoRa приходят в Bitchat как `[Mesh: имя узла] текст` —
   автоматически, без вашего участия.
4. Сообщения из Bitchat копятся в буфере (`[Bitchat] ... (в буфере, ждёт
   ручной синхронизации)`). Чтобы отправить их в LoRa, нажмите `s` и выберите
   направление, количество и период.
5. `l` показывает, сколько сообщений в буферах и включён ли повтор.

## Буферы и синхронизация

* **LoRa → Bitchat.** Хранятся последние **100** сообщений (настраивается
  `history_limit` или `--history N`). Новое сообщение сразу уходит на телефон.
  Если телефон был отключён, при подключении досылаются только недоставленные
  сообщения. Уже доставленные повторно не отправляются.
* **Bitchat → LoRa.** Хранятся последние **100** сообщений. Автоматической
  отправки нет. По команде `s` можно отправить последние 5/10/20/50 — сразу
  или с повтором каждые N минут / N дней. При повторе отправляются только
  новые сообщения. Исключение — режим «полная синхронизация» (`s` → пункт `3`):
  тогда новые сообщения уходят в LoRa сразу.
* Отправка в LoRa идёт по одному сообщению с интервалом `lora_send_interval`
  (по умолчанию 10 секунд). Это защищает эфир от всплесков.
* Очередь и история живут в памяти процесса: при перезапуске приложения
  несохранённые сообщения пропадут.

> Важно: пока телефон **не подключён** к мосту по BLE, мост физически не
> получает новые сообщения из Bitchat — их неоткуда взять. Буфер работает для
> случая «телефон на связи, а радио Meshtastic — нет» и для ручной отправки
> того, что уже пришло с телефона.

## VPN и поиск радио по Wi-Fi

Мост сначала перечисляет **подключённые** сети: адаптер должен быть включён и
иметь рабочий IPv4-адрес. Виртуальные и VPN-адаптеры (VMware, Hyper-V,
TAP/OpenVPN, WireGuard и т.п.) при этом пропускаются, поэтому включённый VPN
не скрывает радио в локальной сети, а лишние подсети не замедляют поиск.

Поиск идёт в два шага и занимает обычно 2–3 секунды на сеть `/24`:

1. Быстрый параллельный перебор адресов выбранной сети по порту (по умолчанию
   4403) — ищутся хосты, у которых порт вообще открыт.
2. Только эти хосты проверяются настоящим рукопожатием Meshtastic, параллельно.
   Поэтому устройство с открытым портом, но не Meshtastic, не попадёт в список.

Если ни одного устройства с открытым портом не найдено, мост пишет об этом и
предлагает:

1. изменить порт поиска;
2. вернуться в основное меню.

IP радио также можно ввести вручную — пункт `4` в меню выбора устройства.

## Как это работает

* BLE: компьютер — **central**, телефон с Bitchat — peripheral. Мост сканирует
  сервис `f47b5e2d-4a9e-4c5a-9b3f-8e1d2c3a4b5c`, подключается к
  характеристике `a1b2c3d4-...`, отправляет подписанный `announce` и слушает
  уведомления. Каждые 60 секунд announce повторяется.
* Связь с телефоном удерживается принудительно: каждые 25 секунд уходит
  короткий announce (keepalive), а если от телефона нет пакетов 90 секунд или
  Windows сообщает, что связи нет, мост закрывает мёртвое соединение и
  подключается заново. Оборванный телефон не попадает в «чёрный список»,
  поэтому переподключение происходит сразу, как только телефон снова рядом.
* Пакеты Bitchat: заголовок v1 (14 байт), подпись Ed25519 над
  «padding»-версией пакета, сжатие zlib (с фолбэком на raw deflate и lz4).
  Входящие фрагменты (`0x20`) собираются; исходящие — режутся по MTU.
* Meshtastic: `meshtastic` Python API. Отправка — `sendText`, приём — pubsub
  `meshtastic.receive`. Эхо собственных сообщений отфильтровывается.

## Ограничения

* Bitchat-сообщения из публичного чата и адресованные (`#N`, `/dm`) мостятся;
  собственные приватные чаты Bitchat (Noise) и файлы — нет.
* При старте выбирается только один телефон Bitchat. Если рядом несколько
  телефонов с Bitchat, мост работает лишь с выбранным; при `0` (не выбирать)
  он подключается к любому найденному.
* Телефон должен быть рядом и Bitchat открыт (iOS в фоне перестаёт
  рекламироваться).
* iOS меняет Bluetooth-адрес телефона, а Windows помнит старые адреса. Поэтому
  при поиске мост проверяет каждый найденный адрес: устройство считается
  телефоном Bitchat только если оно ответило announce. «Фантомные» адреса в
  список не попадают, а ответившие адреса одного телефона объединяются в одну
  строку. Выбранный телефон запоминается по Bitchat peer ID, который при смене
  адреса не меняется.
* Приватность Bitchat: приложение не рекламирует своё имя, поэтому в
  Bluetooth-рекламе нет ни ника, ни пользовательского ID — они читаются только
  при подключении, из announce.
* Bitchat-трафик идёт через один общий LoRa-канал; учитывайте лимиты эфира.
  Поэтому Bitchat → LoRa отправляется только вручную и с интервалом.
* Кириллица в LoRa зависит от настроек канала и клиентов, но обычно работает.
* На ESP32 Wi-Fi и BLE взаимоисключающи: если радио доступно по Wi-Fi, пункт
  «Bluetooth» его не найдёт — это нормально.

## Диагностика

* `--debug` — подробный лог (в том числе все BLE-пакеты).
* `bridge.log` — по умолчанию почти пуст: пишутся только предупреждения,
  файл принудительно очищается каждые 5 минут, после обрыва связи и при выходе.
* `diag/tcp_probe.py <ip>` — сырая проверка Meshtastic API по TCP.
* `diag/mesh_probe.py COM4` — сырая проверка Meshtastic API по serial.

Если BLE-пир не находится:

1. Убедитесь, что Bluetooth включён и Bitchat открыт на телефоне.
2. Проверьте в `--debug`, что устройство рекламирует нужный service UUID.
3. На Linux-исходнике требовалась настройка BlueZ; на Windows это не нужно.

## Живая проверка

1. Запустите `run.bat`, выберите радио и беседу.
2. Дождитесь `[Bitchat] телефон подключён`.
3. Сообщение из LoRa от другого узла появится как `[LoRa] имя: текст` и придёт
   в Bitchat от пира `MeshBridge`.
4. Напишите что-нибудь в Bitchat — в консоли появится
   `[Bitchat] ... (в буфере, ждёт ручной синхронизации)`. Нажмите `s`,
   выберите `Bitchat → Meshtastic`, количество и отправьте.

Один и тот же TCP-порт 4403 обычно обслуживает только одного клиента, поэтому
не подключайтесь к радио другим TCP-клиентом одновременно с мостом.
